## Architecture

**Glrk UI** is a shadcn/ui wrapper and extension library — a Next.js (App Router) documentation site that also serves as a component registry. Users install components via the shadcn CLI pointing at the built registry.

### Key directories

- `components/ui/` — Core component wrappers (46 files). These wrap shadcn/ui primitives with opinionated defaults while keeping full prop pass-through.
- `components/examples/` — Live examples used inside the docs pages.
- `content/docs/` — MDX documentation files powered by Fumadocs.
- `lib/utils.ts` — Shared utilities: `cn()`, type guards, and accessors for the options system.
- `types/` — Shared TypeScript types (`general.d.ts`, `menu.d.ts`).
- `registry.json` — Defines all 46 registry items. Run `pnpm registry:build` after changes here.
- `public/registry/` — Generated output of the registry build (gitignored artifacts).

### Type-safe options system

Select, Combobox, Dropdown, Menubar, and ContextMenu all share a common options type system defined in `types/general.d.ts`:
- `optionT` — `{ label, value, className? }`
- `groupT` — `{ label, options: optionT[] }`
- Separators, disabled states, and sub-menus are handled via type guards in `lib/utils.ts` (`isOption`, `isGroup`, `isSeparator`, `isSubMenu`, etc.)

### Form abstraction

Three complementary form wrappers exist:
- `components/ui/field-wrapper.tsx` — Generic, library-agnostic wrapper
- `components/ui/field-wrapper-rhf.tsx` — React Hook Form integration
- `components/ui/field-wrapper-tf.tsx` — TanStack Form integration

`field.tsx` conditionally renders the right input type based on a `type` prop.

### Data table

`components/ui/data-table/` is a modular TanStack Table integration with optional `@tanstack/react-virtual` virtualization. The `use-table.ts` hook encapsulates table state. Standard and virtualized variants are separate exports.

### Documentation

Fumadocs powers the `/docs` route. `lib/source.ts` configures the source; `mdx-components.tsx` overrides MDX primitives. `components/wrapper.tsx` is the live-example wrapper used in `.mdx` files.

## Configuration notes

- **Path aliases**: `@/*` → root, `collections/*` → `.source/*` (generated by Fumadocs, gitignored)
- **Tailwind v4** via PostCSS plugin — use `cn()` from `lib/utils.ts` for conditional classes
- **Biome** handles both linting and formatting (no ESLint/Prettier)
- **shadcn config** (`components.json`): style `base-nova`, icon lib `lucide`, CSS variables enabled
- `next.config.mjs` marks `ts-morph`, `typescript`, and `shiki` as server-external packages (used during registry build)

## Adding a new component

1. Create wrapper in `components/ui/<name>.tsx`
2. Add example in `components/examples/<name>.tsx`
3. Create docs page `content/docs/shadcn-wrappers/<name>.mdx`
4. Register the component in `registry.json`
5. Run `pnpm registry:build`
